# v2: площадка с несколькими продавцами и платной выдачей контакта

Рабочие заметки для обсуждения с заказчиком. Ничего ещё не реализовано.

## Что хочет заказчик (как сформулировано)

1. **Несколько продавцов.** Заказчик раздаёт своим продавцам секретный код. Продавец с кодом присылает в бота предложение по нашему шаблону. Бот разбирает пост и присылает заказчику уведомление «добавить товар или нет». При одобрении товар уходит **сразу в канал и в приложение**. Ник продавца покупателю **не показываем**, чтобы тот не обошёл площадку до оплаты.
2. **Оплата комиссии.** Покупатель жмёт «Оплатить», его переводит в бота, бот просит оплатить комиссию площадки (например, 1000 ₽). После оплаты бот выдаёт ник продавца, выставившего товар.

## Решения заказчика

| Вопрос | Решение |
| --- | --- |
| Возвраты | не делаем и пока не продумываем; продавец всегда отвечает |
| Обход площадки через ник | не продумываем |
| Приём денег | заказчик оформляет ИП, подключаем ЮKassa через Telegram Payments |
| После оплаты | отдаём ник продавца |
| Цена | в карточке одна цена = цена продавца + комиссия; при оплате видно, что комиссия платится сейчас, а остальное продавцу |
| Размер комиссии | пока не согласован, 1000 ₽ — тестовое значение. Делаем настраиваемым (команда админа, без правки кода) |
| Собственные товары заказчика | тоже с комиссией |
| После оплаты | телефон бронируется на время, второй покупатель оплатить его не может; бронь снимается сама, если продавец не отметил «Продан» |
| Доступ продавцов | персональные одноразовые ссылки-приглашения от админа (`/invite`), продавца можно отключить |
| Подача товара | альбом + подпись по шаблону в бота, превью и переспрос недостающих полей |
| Срок брони | 24 часа |
| Канал публикации | пока тестовый «RaXi тест», потом @apple_raxi (бот — админ с правом публикации) |
| Модераторы | несколько, добавляются владельцем (на нагрузку не влияет: это строки в базе) |
| Чеки | да, чеки делает ЮKassa, покупатель указывает email при оплате |
| Бот | пока тестовый, ключ от бота заказчика дадут позже |
| Тестовый токен ЮKassa | пока нет — делаем тестовый режим оплаты без денег, ЮKassa включается одним секретом |
| Оферта | обязательна при оплате: «Переходя к оплате, вы соглашаетесь с условиями оферты». Текст пишем мы (Максим/Claude), страница — у нас на воркере (бесплатно). Она же нужна ЮKassa для модерации магазина |
| Экран оплаты | объясняем два этапа как в «Айден Маркет»: 1) комиссия площадки через ЮKassa (уже включена в цену), 2) остальное продавцу напрямую. После оплаты выдаём **только ник продавца** |
| Возвраты | в коде не делаем: продавцы проверенные. Пункт про возврат в оферте уточнить у заказчика |
| Номер лота | да: «ЛОТ №…» в посте и карточке + ссылка «Купить лот №…» сразу на карточку в мини-аппе. Номер = id карточки, нагрузки ноль |
| Бронь в канале | нет, бронь видна только в приложении |
| Категории | только iPhone |
| Вопросы по лоту | ссылка на менеджера @Raxi_apple в посте и в карточке; продавца не показываем |
| Доставка / гарантия / трейд-ин | не делаем |

Образцы, которые показал заказчик: бот «Айден Маркет» (@ideniphonerf, двухэтапная оплата + оферта) и @perehvatstore1 (номера лотов, «Купить можно тут» в каждом посте).
| Сервер | платить не хотят — всё должно уложиться в бесплатные лимиты |

## Работа без затрат на сервер

Остаёмся на бесплатном Cloudflare (Workers, D1, Cron). Узкое место — хранение медиа: с несколькими продавцами фото и видео станет кратно больше, а бесплатный KV — это 1 ГБ и 1000 записей в день.

**Идея: не хранить медиа у себя вообще, а использовать Telegram как хранилище.**
- Фото и видео уже лежат в Telegram — у каждого есть `file_id`. В базе храним только его.
- `/media/<id>`: воркер при первом запросе берёт у Telegram `getFile` и скачивает файл. Отдаёт его с кэшем на год, и дальше файл раздаёт edge-кэш Cloudflare (бесплатно и без лимита). Токен бота остаётся на сервере.
- Итог: KV не растёт, запись в него не нужна, чистка проданных не нужна. Лимит один: Bot API отдаёт файлы до 20 МБ — видео тяжелее мы и сейчас пропускаем.
- Для старых постов, импортированных с публичной ленты, `file_id` нет — их оставляем в KV как есть (их мало и они уходят по мере продажи).

**Остальное в бесплатных лимитах с запасом:**
- **Воркер:** 100 тыс. запросов в день. Даже при 1000 открытиях каталога в день выйдет ~15–20 тыс.
- **D1:** чтения и записи на порядки ниже лимита.
- **Оплата:** через Telegram Payments счёт создаёт сам Telegram, у нас только вебхук (`pre_checkout_query` + `successful_payment`). Отдельный сервер или сайт для ЮKassa не нужен.
- **Лимит CPU 10 мс на запрос:** тяжёлого ничего нет. LLM-разбор вызывается только при ошибке регулярок, и у Workers AI есть свой бесплатный суточный лимит.
- **Подзапросы:** до 50 на запуск (публикация альбома, рассылка подписчикам). Рассылку при большом числе подписчиков разбиваем на порции через cron.

**Что всё-таки может стоить денег:**
- домен — не обязателен, `workers.dev` работает;
- комиссия ЮKassa с платежей (~3%) — это не сервер;
- Workers Paid $5/мес — только если площадка сильно вырастет.

## Роли

| Роль | Кто | Что делает |
| --- | --- | --- |
| Владелец (админ) | заказчик и его люди | раздаёт доступ продавцам, модерирует предложения, видит всё и статистику |
| Продавец | перекупы, которым дали доступ | присылает товары, отмечает «продан», получает покупателей |
| Покупатель | любой из канала или мини-аппа | смотрит каталог, платит комиссию, получает контакт |

## 1. Продавцы

### Доступ
- Вариант А — **один общий код** (как просил заказчик): `/start` → «введите код». Просто, но код утекает: его перешлют, и уже не понять, кто кого привёл.
- Вариант Б (**рекомендую**) — **персональная ссылка-приглашение**: админ пишет боту `/invite`, получает `t.me/<бот>?start=s_8f3k2…`. Ссылка одноразовая и живёт 24 часа. Видно, кто подключился, и любого продавца можно отключить (`/sellers`, `/block`).
- Можно и то и другое: общий код для простоты плюс админ подтверждает каждого нового продавца.

### Подача товара
- Продавец шлёт боту **альбом фото/видео + подпись по шаблону** (тот же формат, что в канале: модель, память, состояние, АКБ, ✅/✖️, цена). Разбирает уже готовый парсер.
- Бот сразу показывает продавцу **превью «так увидит покупатель»**. Если не хватает модели, памяти или цены, бот переспрашивает. Дальше продавец жмёт «Отправить на проверку» или «Исправить».
- Альтернатива или дополнение: **форма «Добавить товар» в мини-аппе** (поля + загрузка фото). Ошибок разбора нет вовсе, но это больше работы.

### Модерация
- Админу приходит карточка с фото и разобранными полями. **Админ видит продавца, покупатель — нет.**
- Кнопки: «✅ Опубликовать», «✏️ Изменить цену/текст», «❌ Отклонить» (с причиной, которую бот перешлёт продавцу).

### Публикация
- После одобрения **бот сам публикует пост в канал** (`sendMediaGroup` от имени канала, бот — админ с правом публикации) в фирменном формате магазина.
- Из подписи вырезаем все @ники, телефоны и ссылки продавца. Вместо «Купить: @Raxi_Apple» ставим кнопку или ссылку на мини-апп.
- Фото уходят по `file_id`: без «переслано от», источник не виден. **Риск:** контакты на самих фото (водяной знак, ник на коробке) — это проверяет модератор.
- Пост в канале автоматически попадает в каталог (как сейчас), а карточка запоминает `seller_id`.

### Жизнь товара
- Продавец в боте: `/my` — свои товары с кнопками «Продан», «Изменить цену», «Снять».
- «Продан» — бот правит пост в канале, и карточка уходит из каталога (логика уже есть).
- Изменение цены — сразу или снова через модерацию? (вопрос)

## 2. Оплата комиссии

### Поток
1. Покупатель в карточке жмёт «Купить». Вместо чата продавца открывается **оплата комиссии 1000 ₽**. Счёт можно открыть прямо в мини-аппе (`WebApp.openInvoice`), без перехода в бота.
2. На время оплаты телефон **бронируется** (например, на 15 минут), чтобы два покупателя не заплатили за один телефон.
3. После оплаты:
   - покупателю приходит ник продавца;
   - продавцу — «Покупатель @xxx оплатил доступ к iPhone 16, напишет вам»;
   - админу — запись о сделке и деньги.
4. Карточка в приложении получает статус «Забронирован» до отметки «Продан» или до снятия брони (пост в канале не меняется).

### Способ приёма денег — главный вопрос
| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **ЮKassa через Telegram Payments** (BotFather → Payments) | карта или СБП прямо в Telegram, деньги на счёт заказчика | нужен ИП/ООО/самозанятый, договор с ЮKassa, чеки по 54-ФЗ, ~3% комиссии |
| **ЮKassa / Робокасса по ссылке** (оплата на сайте) | то же + больше способов оплаты | покупатель уходит из Telegram, нужен вебхук |
| **Telegram Stars** | подключается за минуту, никаких договоров | вывод через Fragment в TON, для РФ неудобно, теряется заметная доля |
| **Перевод на карту + скрин** (MVP) | работает сегодня | ручная проверка, не масштабируется, вопросы к налогам |

Нюанс: по правилам Telegram цифровые товары и услуги внутри Telegram должны продаваться за Stars. Платный доступ к контакту — это пограничный случай. Обычно так делают через ЮKassa, но стоит понимать риск.

### Что может пойти не так
- **Продавец не отвечает или телефон уже продан** — нужна политика возврата. Например, продавец должен подтвердить в течение N минут, иначе комиссия возвращается автоматически.
- **Обход в будущем.** Получив ник один раз, покупатель потом напишет продавцу напрямую про другие телефоны. Альтернатива: **анонимный чат через бота**. Покупатель и продавец переписываются через бота и не видят ников, а площадка остаётся посредником. Сложнее, но обход закрыт полностью.
- **Продавец сам обходит площадку** — например, отвечает в канале или оставляет контакт на фото. Это закрывается модерацией и правилами для продавцов.

## План реализации

Каждый этап можно выкатывать и проверять отдельно на тестовом боте и в канале «RaXi тест».

### Этап 1. Роли и настройки
- Миграция D1:
  - `staff` (владелец и модераторы);
  - `sellers` (tg_id, username, статус, кто пригласил);
  - `invites` (код, роль, срок 24 ч, кем использован);
  - `settings` (комиссия, срок брони, канал публикации);
  - в `listings` добавляются `seller_id`, `fee_rub`, `reserved_until`, `reserved_by`.
- Владелец из `ADMIN_IDS` — всегда `owner`. Команды владельца:
  - `/invite` — ссылка-приглашение для продавца;
  - `/invite_mod` — ссылка для модератора;
  - `/sellers`, `/mods` — списки с кнопками «Отключить»;
  - `/fee 1500` — комиссия;
  - `/channel` — куда публиковать.
- Переход по ссылке `t.me/<бот>?start=s_<код>` делает человека продавцом, `m_<код>` — модератором. Ссылка одноразовая.

### Этап 2. Медиа без хранилища
- Для новых товаров в базе только `file_id`. `/media/f/<id>` берёт файл у Telegram (`getFile`) и отдаёт с кэшем на год, дальше его раздаёт edge-кэш.
- Старые импортированные карточки работают через KV как сейчас.

### Этап 3. Продавец подаёт товар
- Продавец шлёт альбом с подписью по шаблону. Бот собирает альбом (части приходят отдельными апдейтами — как с каналом) и разбирает подпись.
- Бот отвечает превью «так увидят покупатели» с кнопками «Отправить на проверку» и «Отменить».
- Если нет модели, памяти или цены, бот переспрашивает. Продавец присылает исправленную подпись, и превью обновляется.
- Шаблон бот присылает по команде `/template` и при первом входе продавца.
- `/my` — товары продавца со статусами «на проверке / в каталоге / забронирован / продан» и кнопками «Продан» и «Снять».

### Этап 4. Модерация
- Каждому сотруднику (владелец + модераторы) приходит карточка: фото, разобранные поля, цена продавца и итоговая цена с комиссией, продавец. Кнопки: «✅ Опубликовать», «❌ Отклонить», «💰 Изменить цену».
- Кто первым нажал, тот и решил: у остальных сообщение обновляется на «Опубликовал @модератор».
- При отклонении бот спрашивает причину и пересылает её продавцу.

### Этап 5. Публикация в канал
- Бот публикует альбом в канал от имени канала (`sendMediaGroup`). Подпись — в фирменном формате магазина: «ЛОТ №<id>», цена с комиссией, без контактов продавца. Внизу:
  - «Купить лот №<id>» — ссылка сразу на карточку в мини-аппе (`t.me/<бот>?start=l_<id>` уже работает; для прямого открытия `t.me/<бот>/<app>?startapp=<id>` нужно один раз зарегистрировать приложение в BotFather `/newapp`);
  - «Вопрос по лоту — @Raxi_apple» (менеджер).
- **Важно:** Telegram не присылает боту его собственные посты, поэтому карточку в каталоге создаём сразу по ответу `sendMediaGroup`, а не через `channel_post`.
- «Продан» от продавца или модератора — бот правит подпись поста (`editMessageCaption`), и карточка уходит из каталога.

### Этап 6. Оплата комиссии и бронь
- В карточке кнопка «Купить — 58 990 ₽». По нажатию открывается экран оформления, по образцу «Айден Маркет»:
  - «Вы оформляете покупку iPhone 16 128GB (лот №…). Оплата проходит в два этапа, которые вместе составляют итоговую цену»;
  - «1. Услуги площадки — 1 000 ₽. Уже включены в цену, оплата через ЮKassa картой или СБП»;
  - «2. Вторая часть — 57 990 ₽ — продавцу напрямую»;
  - «Переходя к оплате, вы соглашаетесь с условиями оферты» (ссылка на страницу оферты).
- Дальше счёт `createInvoiceLink` и `WebApp.openInvoice` — оплата прямо в мини-аппе.
- **`pre_checkout_query`:** проверяем, что товар ещё не забронирован и не продан. Если занят — отказ с понятным текстом, деньги не списываются.
- **`successful_payment`:**
  - бронь на 24 ч;
  - покупателю приходит **только ник продавца** и короткое напоминание: остаток оплачивается продавцу, бронь 24 часа;
  - продавцу — «@покупатель оплатил iPhone 16, напишет вам»;
  - сотрудникам — запись о сделке.
- В **приложении** у товара метка «Забронирован», купить его нельзя (пост в канале при брони не меняем). Cron снимает просроченную бронь, если продавец не отметил «Продан».
- **Чеки:** в счёт передаём данные для чека (`provider_data` с позицией «Комиссия площадки»), Telegram спрашивает email, ЮKassa сама присылает чек.
- **Тестовый режим:** пока нет токена ЮKassa, вместо счёта бот присылает кнопку «Оплатить (тест)». Сценарий проходит целиком без денег. Подключение ЮKassa — один секрет `PAYMENT_PROVIDER_TOKEN`.
- Свои товары владельца (посты, которые он пишет в канал сам) работают так же. Продавец у них — сам владелец, его ник и выдаём.

### Этап 7. Мини-апп, оферта и статистика
- **Мини-апп:**
  - метка «Забронирован»;
  - «ЛОТ №…» в карточке;
  - «Вопрос по лоту» → @Raxi_apple;
  - новый экран оплаты с двумя этапами и ссылкой на оферту;
  - в API никогда не уходит ник или id продавца;
  - цена везде одна — с комиссией.
- **Оферта:** текст готовим мы (черновик — `docs/oferta.md`, реквизиты ИП подставить после регистрации), страница `/oferta` отдаётся воркером как статика. Модель как у «Айден»: площадка объявлений, сделка напрямую между покупателем и продавцом, комиссия — плата за услуги площадки. Пункт о возврате уточнить у заказчика.
- **`/stats`:** оплаты за неделю, сумма комиссий, топ продавцов по продажам (видят только сотрудники).
- **Только iPhone** — категории не расширяем, шаблон и фильтры как сейчас.

### Нагрузка и бесплатные лимиты
- Рост идёт только в D1 (строки на товары, сделки, людей) — это килобайты. KV для новых товаров не используется.
- Подзапросы на один запуск укладываются в 50:
  - публикация альбома — 1–2 запроса;
  - модерация — по сообщению на каждого сотрудника;
  - рассылки подписчикам при росте базы — порциями через cron.
