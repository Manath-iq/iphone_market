# RaXi Store — каталог iPhone в Telegram

Бот + мини-апп для перекупщика б/у айфонов (канал @apple_raxi). Продавец постит в канал как обычно, бот сам ведёт каталог «только то, что в наличии». Исходное ТЗ — `ТЗ бот + мини-апп «Каталог RaXi Apple».md`.

**Статус:** v2 «площадка с несколькими продавцами и платной выдачей контакта» реализована (этапы 1–7, 26.10.2026) и проверена на тестовом боте и в «RaXi тест». Оплата работает в тестовом режиме. Для запуска у заказчика ждём: бота заказчика, токен ЮKassa, реквизиты ИП для оферты (см. «Демо-допущения»). **Решения v2 — в `docs/v2-marketplace.md`, читать перед любыми изменениями.**

Кратко о v2 (подробно — в документе):
- **Продавцы:** входят по одноразовым ссылкам-приглашениям, присылают альбом по шаблону в бота. Модераторы одобряют, бот публикует в канал без контактов продавца.
- **Цена:** в карточке одна — цена продавца + настраиваемая комиссия.
- **Оплата:** в два этапа, как в «Айден Маркет»: комиссия через ЮKassa (Telegram Payments) с офертой, остаток — продавцу напрямую. После оплаты выдаём **только ник продавца**. Бронь 24 часа, видна **только в приложении**. Возвратов в коде нет.
- **Лоты и вопросы:** номер лота в посте и карточке («Купить лот №…»), вопросы по лоту — менеджеру @Raxi_apple.
- **Ограничения:** только iPhone. Доставку, гарантию и трейд-ин не делаем.
- **Оферта:** её текст пишем мы. Черновик — `docs/oferta.md`: реквизиты ИП заглушками, пункты [УТОЧНИТЬ] ждут заказчика, перед запуском — проверка юристом.

## Как устроено сейчас

- **Синхронизация с каналом:**
  - `channel_post`/`edited_channel_post` → `worker/src/ingest.ts`;
  - пост с `#АКТУАЛЬНО_RaXi` → карточка; хэштег убрали (продавец пишет «❌ Продано ❌») → `sold`;
  - удалённые посты ловит cron раз в час через `t.me/<канал>/<id>?embed=1`.
- **Альбомы.** Части альбома приходят отдельными апдейтами в любом порядке. Медиа сначала пишется «ничейным», потом привязывается к карточке по `media_group_id` (`addMedia` + `attachGroupMedia`). Скачивание с «захватом» (`claimed_at`, миграция 0002), чтобы параллельные апдейты не качали одно и то же.
- **Медиа.** Файлы из Telegram (посты канала, товары продавцов) в KV не копируются: `media.storage_key = 'f/<id>'`, `/media/f/<id>` берёт файл по `file_id` (`getFile`) и отдаёт потоком. Кэширует **Workers Caching** на отдельной точке входа `MediaCache` (`wrangler.toml`: `[exports.MediaCache.cache]`), он же режет Range для iOS. В KV (`m/...`) остаются только старые файлы и импорт ленты; cron чистит проданные старше 7 дней.
- **API:**
  - `GET /api/listings`, `/api/listings/:id`, `/api/facets`, `/api/store`;
  - `POST /api/events`, `/api/checkout` (счёт или тестовая оплата);
  - `GET/POST/DELETE /api/subscriptions`.
  - `initData` проверяется HMAC на каждом `/api/*`; `PUBLIC_READ=1` разрешает чтение без него (демо).
  - **В API никогда не уходят ник и id продавца**: `toListing` собирает поля явно, тест в `worker/test/listing.test.ts`. Покупателю — только `reserved` и `reserved_by_me`.
- **Роли (v2).** Владелец — из `ADMIN_IDS`. Модераторы и продавцы приходят по одноразовым ссылкам `/invite_mod` и `/invite` (`?start=m_<код>` / `s_<код>`, 24 ч). Продавцу без @username ссылку не тратим.
- **Путь товара продавца:**
  - альбом с подписью → заявка `submissions` (превью шлёт один из апдейтов альбома после паузы, атомарный `claimPreview`);
  - превью в фирменном формате без контактов → «На проверку»;
  - карточка у всех сотрудников: «Опубликовать / Изменить цену / Отклонить / Все фото». Решает первый — атомарный `moveStatus`;
  - публикация: скрытая карточка (ради номера лота) → `sendMediaGroup` в канал из `/channel` → карточка и медиа по ответу;
  - «Продан» и «Снять» в `/my` (и `/sold`, `/hide` у сотрудников) правят подпись поста.
  - Посты бота `upsertPost` не трогает (`seller_id IS NOT NULL`).
- **Цены.** `price_rub` — итоговая цена покупателя везде (фильтры, подписки). `seller_price_rub` и `fee_rub` — части, комиссия фиксируется при создании карточки. Посты владельца: `/fee_mode plus` — комиссия сверху цены поста (сейчас), `incl` — внутри (`ownerPrices` в `ingest.ts`).
- **Оплата и бронь:**
  - `pre_checkout_query` удерживает лот 10 минут атомарным `holdListing`;
  - `successful_payment` (или тестовая кнопка `tpay:`) → бронь `reserve_hours` (24 ч), покупателю — только ник продавца (у постов владельца — `STORE.sellerUsername`);
  - бронь видна только в приложении, просроченная снимается лениво; cron сообщает об истёкших;
  - `/unreserve <id>` — снять вручную.
- **Бот:**
  - покупателю — `/start` (со счётчиком), `/start l_<id>` (поделиться, «Купить лот»);
  - продавцу — `/template`, `/my`;
  - сотрудникам — `/list`, `/stats`, `/sold|/hide|/show|/unreserve id`, `/help`;
  - владельцу — `/invite`, `/invite_mod`, `/sellers`, `/mods`, `/fee`, `/fee_mode`, `/channel`;
  - превью новой карточки с фото и кнопками «Всё верно / Скрыть / Вернуть»;
  - уведомления подписчикам с фото;
  - статистика по понедельникам в 10:00 МСК.
- **Картинки к сообщениям бота** (стиль логотипа канала: розовый неон на тёмном фоне):
  - `welcome` — `/start`; `seller` — приглашение продавца и `/template`; `moderator` — приглашение модератора; `paid` — контакт продавца после оплаты;
  - исходники в `design/bot-cards/*.html`; `node scripts/render-cards.ts` снимает живой мини-апп (каталог, карточка первого лота) и рендерит `app/public/cards/*.jpg`. Он же пишет `worker/src/cards-version.ts` с хэшами;
  - `sendWithCard` (`cards.ts`) шлёт картинку по ссылке один раз и хранит её `file_id` в `settings` (`card:<имя>:<хэш>`). Перерисовали картинку → новый хэш → после деплоя загрузится заново.
- **Мини-апп:**
  - тема из `themeParams`, Liquid Glass; логотип канала (`app/public/logo.jpg`) в шапке и на вкладке «Магазин»;
  - полноэкранный режим на телефонах;
  - `MainButton` «Купить — X ₽» → лист оформления в два этапа (`Checkout.tsx`) → «Оплатить» (`openInvoice` или тестовая кнопка в боте); `BackButton` со стеком слоёв (`pushBack/popBack` в `tg.ts`);
  - «Лот №», метка «Забронирован», «Вопрос по лоту — @Raxi_apple»;
  - оферта — статическая `app/public/oferta.html` (собрана из `docs/oferta.md`), адрес `/oferta`;
  - вкладки Каталог / Подписки / Магазин (монтируются при первом заходе);
  - `?tab=subs` и `?l=<id>` в URL.

## Грабли, на которые уже наступили (не повторять)

- **grammY на вебхуке:** `bot.catch` не срабатывает. Любая ошибка → 500 → Telegram бесконечно повторяет апдейт (дубли). Все обработчики висят на `bot.errorBoundary(...)` — новые тоже регистрировать на нём (`h.on/h.command/h.callbackQuery` в `bot.ts`).
- **Telegram не присылает боту его собственные посты в канале.** Если бот сам публикует (v2), карточку создавать по ответу `sendMediaGroup`, а не ждать `channel_post`.
- **Bot API** отдаёт файлы как `application/octet-stream` — тип ставить самим. Лимит `getFile` — 20 МБ, видео больше пропускаем. Ссылки `api.telegram.org/file/...` содержат токен — в браузер не отдавать.
- **`overflow-x: hidden` на `body`** ломает `position: sticky` и прокрутку окна. Используем `overflow-x: clip` на `.app`.
- **Нет подписи на `onLoad`.** Закэшированные картинки могли не получить `onLoad` и оставались прозрачными. Использовать компонент `Img` (проверяет `complete`).
- **Состояние в обработчиках.** Быстрые клики затирали друг друга — обновлять через функцию: `setF(prev => …)`.
- **`t.me/<user>?text=`** подставляет текст не во всех клиентах; копирование в буфер из `MainButton` не работает (это не DOM-жест).
- **Бесплатный тариф: 50 внешних подзапросов на запуск** (запросы к D1/KV считаются отдельно, лимит 1000). Cron: 15 проверок постов + 12 файлов импорта + 6 уведомлений + 3 истёкшие брони. Публикация: альбом + правка карточек у сотрудников + до 15 подписчиков (остальным дошлёт cron). Не раздувать.
- **Workers Caching включать только на `MediaCache`.** На основной точке входа он закэшировал бы `/api/*` (без `Cache-Control` — на 2 часа) и считал запросы к статике. Кэш медиа общий для версий (`cross_version_cache`).
- **`sendMediaGroup` принимает 2–10 элементов.** Одно фото или видео слать `sendPhoto/sendVideo` — это делает `sendAlbum` в `notify.ts`.
- **Долгая работа в обработчике callback.** Публикацию запускать в `waitUntil` после `answerCallbackQuery`: grammY на вебхуке через 10 с отвечает Telegram, и незавершённая работа может оборваться.
- **`.overlay` карточки с `transform`.** `position: fixed` внутри неё не прижимается к экрану. Листы поверх карточки рендерить через `Portal` в `Detail.tsx` (без `preact/compat` — он стоит +2,5 КБ).
- **zsh:** переменная с флагами (`$C`) не разбивается на аргументы — флаги wrangler писать явно.
- **Python на машине без SSL-сертификатов** (`urllib` падает) — HTTP-запросы делать через `curl`.
- **Скриншоты мини-аппа для картинок.** Headless Chrome не делает окно уже ~450 px, а в iframe не проигрываются анимации появления карточек. Поэтому `render-cards.ts` управляет Chrome по DevTools: эмуляция телефона 390×844, светлая тема.
- **iOS Simulator недоступен** (не принята лицензия Xcode, нужен `sudo`). На iPhone пользователь проверяет сам.

## Как проверять

- **Мини-апп в режиме Telegram** без телефона:
  - открыть URL с хэшем `#tgWebAppData=<подписанный initData>&tgWebAppVersion=8.0&tgWebAppPlatform=ios&tgWebAppThemeParams=<json>`. `initData` подписывается токеном бота (HMAC «WebAppData»);
  - вызовы SDK видны в консоли как `[Telegram.WebView] > postEvent …`;
  - события эмулируются через `Telegram.WebView.receiveEvent('main_button_pressed' | 'back_button_pressed' | 'safe_area_changed' …)`.
- **Бот:**
  - POST апдейтов на `/bot` с заголовком `X-Telegram-Bot-Api-Secret-Token`;
  - для фото нужны настоящие `file_id` — получить через `sendPhoto` боту в чат админа и удалить сообщение;
  - тестовые данные после проверки удалять: строки в D1 и ключи в KV.
- **Живой сценарий:** в канале «RaXi тест» (Telegram Desktop) — пост или альбом с `#АКТУАЛЬНО_RaXi` → карточка; правка хэштега → карточка снята.
- **Каталог видят реальные пользователи** — тестовые карточки не оставлять.
- **Сценарий v2 с одного аккаунта:** владелец может принять `/invite` и стать продавцом — заявка, карточка модерации, публикация и тестовая оплата приходят в один чат. После проверки удалять: `submissions`, `submission_media`, `mod_messages`, `payments`, карточки с `seller_id`, их `media`; посты в «RaXi тест».
